## Outcome

Task 12 implements the opt-in Explore feed for credible adjacent careers. A pure deterministic domain module (`packages/domain/src/explore.ts`) holds a curated UK pathway taxonomy — each pathway a role family with 5–12 weighted core skills — and an evaluator that credits only exact normalised-concept matches against **confirmed** evidence in the `skill`, `tool`, and `responsibility` categories. A pathway is suggested only when it reaches at least 70% weighted overlap (integer arithmetic, inclusive), carries no more than two significant unmatched core skills, and sits outside the user's active target role families (career-draft target families plus every enabled saved search's role families). Keyword or label coincidence earns nothing, and no AI participates anywhere in the path.

Migration `202607190002_explore_pathways.sql` seeds the curated `explore_pathways` reference table (kept in lockstep with the domain taxonomy by a repository test) and adds owner-only `career_explore_settings` (opt-in, disabled by default) and `career_pathway_decisions` (dismissed/promoted, one row per owner and pathway) with forced RLS and read-only authenticated grants; both mutate only through security-definer RPCs (`set_explore_enabled`, `decide_career_pathway`) that check approved access and take the per-owner generation mutex first. The decision RPC additionally rejects any concept outside the curated taxonomy, and foreign keys enforce the same boundary at the schema level. Aggregate analytics live in the deliberately ownerless `explore_pathway_analytics` table whose schema admits only a curated, grammar-constrained pathway concept, a bounded event name, and a counter — no owner column exists and non-curated text cannot enter, so no CV snippet or identifying text can be stored; counters record decision _transitions_ only, so repeat toggles never inflate them. Career-profile deletion now also erases explore settings and pathway decisions; the ownerless aggregate counters survive by design because they identify nobody. pgTAP file 013 adds 29 assertions and the static verifier now enforces 12 migrations and 25 forced-RLS tables.

The web layer (`apps/web/src/lib/explore/`) mirrors the target-feed architecture: a pure `buildExploreResult` shared by the fictional development repository and the caller-bound Supabase repository, RPC-only mutations, and a `promote` flow that rebuilds the suggestion server-side (never trusting client labels), carries the matched confirmed-evidence normalised concepts — partitioned into skill/tool versus responsibility exactly as the `save_search_profile` RPC validates them — into an enabled named search profile, re-enables an existing search for the same role family instead of creating a duplicate, then records the promotion. The opt-in check runs before any profile-snapshot fetch, and the enabled path loads the snapshot and decisions in parallel. `/explore` gives the disabled state an honest opt-in explanation, and the enabled state suggestion cards with an accessible overlap figure, matched skills with the confirmed evidence labels used, gaps with significant ones marked, dismiss/restore and promote controls, a quiet disable control, and a threshold-explaining empty state. Explore joined the desktop rail and mobile navigation.

## Review remediation record

The independent review waves surfaced these findings, all remediated test-first at `f692574`:

1. **Promotion failed against the real database (critical).** The promoted search draft used pathway display labels as `skillConcepts`, but `save_search_profile` only accepts concepts that exactly equal confirmed owner evidence normalised concepts, validated per category. The suggestion contract now exposes each matched skill's normalised concept and the evidence categories that earned the credit, and `buildPromotedSearchDraft` partitions them into `skillConcepts` (skill/tool) and `responsibilityConcepts` (responsibility).
2. **Arbitrary grammar-valid text could reach the ownerless analytics.** `decide_career_pathway` validated only the concept grammar, so a directly-invoked RPC call could persist a non-curated string. The curated `explore_pathways` seed table, an explicit RPC membership check, and foreign keys on both the decisions and analytics tables now enforce the taxonomy at the database boundary; a repository test keeps the SQL seed in lockstep with the domain taxonomy.
3. **Analytics counted actions, not transitions.** Repeat toggles of the same decision inflated the aggregate; the upsert now updates only on a real decision change and the counter increments only when a row changed.
4. **Re-promotion could duplicate search profiles.** Promoting a pathway whose earlier promoted search had been disabled created a second search; `promote` now re-enables the existing search for that role family instead.
5. **Wasted work.** `getExplore` fetched the full profile snapshot even while Explore was disabled and ran its reads serially; the opt-in check now runs first and the enabled path fetches snapshot and decisions in parallel.
6. **Duplication and honesty cleanups.** The normalised-concept schema is now exported once from `@jobwarden/domain` (replacing three hand-copied regexes), the explore action feedback markup is one shared component, the dead export of the role-family helper was removed, and the badge for a re-suggested previously-promoted pathway reads "Promoted earlier".

Accepted, documented residuals: the promote flow's search creation and decision record are two sequential RPCs, not one transaction — a failure between them leaves a correct search with an unrecorded promotion, and the idempotent re-enable makes a retry safe; dismissals are membership-checked at the database (curated taxonomy) rather than against the live suggestion list; the shared mutation-origin/action scaffolding duplication follows the existing jobs/profile convention and was left for a future consolidation task.
