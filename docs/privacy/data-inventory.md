# Personal Data Inventory

**Reviewed:** 2026-07-18 for the Task 10 release-gate record

Real-user processing is not active. This inventory records the implemented data model and the production gates that must be exercised before JobWarden accepts personal data.

The database-owned `career_cv_uploads_enabled` setting defaults false and blocks upload intents, Storage writes, CV registration, and extraction claims. The web capability is also hard-disabled. Both independent gates remain closed in Task 10.

| Data                                | Location                             | Purpose                                                              | Access boundary                                                                                   | Retention/deletion                                                                                                                 |
| ----------------------------------- | ------------------------------------ | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Private CV object                   | Supabase Storage `career-documents`  | User-requested profile extraction                                    | Approved owner path; generation-bound insert intent; service role for extraction/cleanup          | Until replacement, CV deletion, profile deletion, or erasure; all nested/unregistered objects are inventoried before full deletion |
| CV upload intent                    | `public.career_cv_upload_intents`    | Bind one owner path to the current profile generation                | Forced RLS; owner-derived begin RPC; Storage policy validates the live intent and generation      | Expires after 15 minutes, is consumed by registration, and is deleted when full deletion advances the generation                   |
| CV metadata                         | `public.cv_documents`                | Validate ownership, type, size, checksum, lifecycle, and replacement | Forced RLS owner read; owner-derived/service RPC mutation; registration checks Storage and intent | Cascades only after exact object removal; inactive failed/replaced rows are purged after their object                              |
| Raw structured extraction proposal  | `public.cv_extraction_runs.proposal` | Idempotent handoff into review records                               | Forced RLS owner read; token/lease-fenced service completion                                      | Cleared automatically within 24 hours; status/counts/timestamps remain                                                             |
| Extraction run metadata             | `public.cv_extraction_runs`          | Idempotency, lease state, bounded failure diagnosis                  | Forced RLS owner read; service-only claim/renew/complete                                          | Cascades with its CV/profile                                                                                                       |
| Career evidence and bounded excerpt | `public.career_evidence_items`       | Explainable user-reviewed personalisation                            | Forced RLS owner read; only owner-derived decision/save RPCs mutate confirmation/profile evidence | Cascades with CV or profile; changes transactionally prune no-longer-confirmed search concepts                                     |
| Profile preferences and seniority   | `public.career_profiles`             | Career direction and future deterministic matching                   | Forced RLS owner read; generation-fenced owner-derived save RPC                                   | Deleted by full-profile deletion or erasure                                                                                        |
| Profile generation tombstone        | `public.career_profile_generations`  | Reject stale save/upload/delete work after erasure                   | Forced RLS owner read; shared owner mutex is mutated only inside reviewed database boundaries     | Survives profile deletion, advances before the profile cascade, and remains until the authentication identity is erased            |
| Machine suggestions and decisions   | `public.profile_suggestions`         | Evidence-bound optional proposals                                    | Forced RLS owner read; owner-derived decision RPC                                                 | Cascades with extraction run/profile                                                                                               |
| Named search profiles               | `public.search_profiles`             | User-controlled Target Feed inputs                                   | Forced RLS owner read; generation-fenced save RPC permits only unique confirmed owner evidence    | Deleted by full-profile deletion/erasure; stale evidence concepts are pruned transactionally                                       |
| AI daily aggregate                  | `public.career_ai_daily_usage`       | Enforce the hard application-wide optional-AI allowance              | No authenticated table access; service operation only                                             | One UTC-date/count aggregate; deliberately has no user/profile foreign key and survives user/profile deletion                      |
| Function operational log            | Hosted function log sink             | Diagnose bounded runtime failures                                    | Platform operators under least privilege                                                          | Correlation ID, counts, duration, model, and sanitised code only; platform retention must be set before activation                 |

Full-profile deletion derives the owner from the verified session, recursively inventories the complete owner Storage prefix in bounded stable pages, includes nested and uploaded-but-unregistered objects, unions registered metadata paths, removes unique paths in bounded batches, and verifies the prefix is empty before calling the database deletion RPC. The RPC independently rejects while any matching Storage object remains, then advances the durable generation, clears upload intents, and deletes the profile cascade. A list, removal, or post-removal inventory failure leaves structured data intact for retry.

Excluded everywhere outside the private source object and transient in-memory parser/provider request: raw CV text, contact details, full sections, request bodies, prompts, provider outputs, tokens, cookies, object bytes, and file paths. They must not enter Git, fixtures, URLs, analytics, error tracking, email, audit metadata, or application logs.

Cloudflare Workers AI is an optional subprocessor only when the owner has rechecked its current data-use/retention terms and enabled a non-zero private allowance. The deterministic path needs no AI provider. Supabase is the intended database, authentication, function, scheduler, and private Storage processor. Task 16 owns the final privacy notice, subprocessors/transfer assessment, export, erasure exercise, incident process, and live retention configuration.

Docker-backed reset/pgTAP, live approved authentication, private Storage/RLS, fictional replacement/deletion/retention exercises, and complete erasure verification remain mandatory before activation. See [Career Profile Data Operations](../operations/career-profile-data.md) for exact ordering.
