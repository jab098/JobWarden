# Personal Data Inventory

**Reviewed:** 2026-07-18 for the Task 10 local implementation

Real-user processing is not active. This inventory records the implemented data model and the production gates that must be exercised before JobWarden accepts personal data.

The database-owned `career_cv_uploads_enabled` setting defaults false and blocks Storage writes, CV registration, and extraction claims. The web capability is also hard-disabled. Both independent gates remain closed in Task 10.

| Data                                | Location                             | Purpose                                                              | Access boundary                                                                          | Retention/deletion                                                                                                |
| ----------------------------------- | ------------------------------------ | -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Private CV object                   | Supabase Storage `career-documents`  | User-requested profile extraction                                    | Approved owner path; server service role for extraction/cleanup; no administrator policy | Until replacement, CV deletion, profile deletion, or erasure; Storage removed before metadata                     |
| CV metadata                         | `public.cv_documents`                | Validate ownership, type, size, checksum, lifecycle, and replacement | Forced RLS owner read; owner-derived/service RPC mutation                                | Cascades after exact object removal; inactive failed/replaced rows are purged after their object                  |
| Raw structured extraction proposal  | `public.cv_extraction_runs.proposal` | Idempotent handoff into review records                               | Forced RLS owner read; service completion                                                | Cleared automatically within 24 hours; status/counts/timestamps remain                                            |
| Extraction run metadata             | `public.cv_extraction_runs`          | Idempotency, bounded operational state, sanitised failure diagnosis  | Forced RLS owner read; service completion                                                | Cascades with its CV/profile                                                                                      |
| Career evidence and bounded excerpt | `public.career_evidence_items`       | Explainable user-reviewed personalisation                            | Forced RLS owner read; explicit owner confirm/exclude                                    | Cascades with CV or profile; user-origin evidence with profile                                                    |
| Profile preferences and seniority   | `public.career_profiles`             | Career direction and future deterministic matching                   | Forced RLS owner-only                                                                    | Deleted by full-profile deletion or erasure                                                                       |
| Machine suggestions and decisions   | `public.profile_suggestions`         | Evidence-bound optional proposals                                    | Forced RLS owner read; owner-derived decision RPC                                        | Cascades with extraction run/profile                                                                              |
| Named search profiles               | `public.search_profiles`             | User-controlled Target Feed inputs                                   | Forced RLS owner-only                                                                    | Deleted by full-profile deletion or erasure                                                                       |
| AI daily counter                    | `public.career_ai_daily_usage`       | Enforce hard optional-AI allowance                                   | No authenticated table access; service operation only                                    | Cascades with profile; contains no CV/prompt/output text                                                          |
| Function operational log            | Hosted function log sink             | Diagnose bounded runtime failures                                    | Platform operators under least privilege                                                 | Correlation ID, counts, duration, model and sanitised code only; platform retention must be set before activation |

Excluded everywhere outside the private source object and transient in-memory parser/provider request: raw CV text, contact details, full sections, request bodies, prompts, provider outputs, tokens, cookies, object bytes, and file paths. They must not enter Git, fixtures, URLs, analytics, error tracking, email, audit metadata, or application logs.

Cloudflare Workers AI is an optional subprocessor only when the owner has rechecked its current data-use/retention terms and enabled a non-zero allowance. The deterministic path needs no AI provider. Supabase is the intended database, authentication, function, scheduler, and private Storage processor. Task 16 owns the final privacy notice, subprocessors/transfer assessment, export, erasure exercise, incident process, and live retention configuration.

See [Career Profile Data Operations](../operations/career-profile-data.md) for exact replacement, cleanup, expiry, deletion, and activation ordering.
